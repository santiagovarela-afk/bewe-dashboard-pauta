## Arquitectura del filtro de fechas (lo que pediste · cómo quedó)

**Antes**: cada vez que cambiabas el preset de fechas el frontend re-llamaba `/api/meta`.

**Ahora**:
1. `refresh()` del store llama 4 endpoints en paralelo: campañas + adsets agregados + campañas + adsets con `time_increment=1` (breakdown diario).
2. Datos crudos van a `rawCampaigns`, `rawAdsets`, `daily[]`.
3. `dateRange{from,to}` (con presets: Hoy · Ayer · 3d · 7d · 14d · Este mes · custom) controla un memo que **agrega los daily rows** por campaña → `campaigns` y `adsets` filtrados.
4. **Cambiar el filtro NO hace fetch**. Solo recalcula el memo.
5. El connector daemon detecta cambios en `.env.local` y push hot-reload al server (`process.env.META_TOKEN`) sin reinicio.

Además: caché de 2 capas:
- **Cliente**: `useMetaFetch` con localStorage TTL 5min · stale-while-revalidate.
- **Servidor**: Map en memoria con TTL 30s · headers `X-Cache: HIT|MISS|EXPIRED|BYPASS` · `_nocache=1` bypasea.

## AI Memory · cómo funciona

`lib/ai-memory.ts` define el sistema:
- **Reglas inviolables** (12): plan, presupuesto, thresholds CPT, reglas Julián día 7/14, C3 anomalía, watchpoint CO, formato de respuesta.
- **Entries cronológicos**: cualquier persona (o el bot) puede agregar entrada con `topic + body + ref opcional + source`.
- **Inyección al prompt**: `buildPlanContext(campaigns, daysElapsed, memory)` concatena el bloque memoria al system prompt de Gemini.
- **UI**:
  - Tab Config → tarjeta "Memoria del agente" lista las 20 más recientes + reglas + botones (eliminar / agregar manual / resetear reglas).
  - En cada respuesta del bot dentro del AI dock → botón "Recordar" abre modal pre-rellenado y guarda.

Persistencia: `.data/ai-memory.json` (atomic write, gitignored).
